Power BI

Diretrizes práticas para criação de dashboards eficientes, acessíveis e orientados a decisão. Foco em propósito, clareza e acionabilidade.

Regra de Ouro: Todo dashboard deve responder claramente: "Qual decisão isso apoia?" Se você não consegue articular a decisão que o dashboard facilita, ele não deveria existir.

1. Princípios Fundamentais

Fundamentos inegociáveis para dashboards que realmente funcionam. Priorize sempre decisão sobre decoração.

Propósito antes de forma

Cada visual deve servir uma decisão específica. Bordas decorativas, efeitos 3D e gradientes raramente servem ao propósito. Remova tudo que não apoia diretamente a ação.

Hierarquia visual clara

Guie o olho do usuário do mais importante ao detalhe. Use tamanho, posição e contraste estrategicamente. KPIs críticos devem dominar visualmente.

Menos é mais

Um dashboard sobrecarregado é um dashboard inútil. Limite a 5-7 KPIs por página. Se precisa de mais, crie páginas separadas ou use drill-down.

Legibilidade é sagrada

Tamanho de fonte mínimo: 10pt para labels, 12pt para texto corrido. Contraste WCAG AA obrigatório. Nunca sacrifique legibilidade por estética.

Cores com propósito

Verde/vermelho apenas para positivo/negativo. Use paleta categórica para séries. Nunca use mais de 6 cores simultâneas (daltonismo).

Contexto temporal

Sempre mostre comparações: vs. período anterior, vs. meta, vs. forecast. Um número isolado não informa decisão.

3. Escolha de Gráficos

O tipo de gráfico determina se o insight será imediato ou perdido. Escolha com base no tipo de comparação necessária.

Tipo de Gráfico Quando Usar Quando NÃO Usar
Barra Horizontal Ranking, comparação de categorias (top 10 produtos) Evolução temporal, parte-do-todo
Barra Vertical Comparação temporal discreta (vendas por mês) Mais de 12 categorias (ilegível)
Linha Tendências ao longo do tempo (30+ pontos) Comparação de categorias sem ordem
Pizza Parte-do-todo com 2-3 fatias Mais de 5 fatias, comparação temporal
Cartão (KPI) Métrica única crítica (receita total, NPS) Comparar múltiplas categorias
Tabela Valores precisos, múltiplas dimensões Mostrar tendências (use gráfico)
Scatter Plot Correlação entre 2 variáveis Séries temporais simples
Mapa Distribuição geográfica relevante Geografia irrelevante para decisão
Nunca use: Gráficos 3D, gauge com ponteiro, gráficos de rosquilla com mais de 5 fatias, WordClouds em contexto executivo.

4. Checklist Crítico

Verifique estes pontos antes de publicar qualquer dashboard. Um "não" em qualquer item exige correção imediata.

Antes de Publicar
Propósito claro: Consigo explicar em uma frase qual decisão este dashboard apoia?
Hierarquia visual: O KPI mais importante é o maior elemento da página?
Contexto temporal: Todos os KPIs têm comparação (vs. mês anterior, vs. meta, etc)?
Legibilidade: Todos os textos têm no mínimo 10pt e contraste adequado?
Cores semânticas corretas: Verde/vermelho usados apenas para positivo/negativo?
Máximo de cores: Nenhum gráfico usa mais de 6 cores simultâneas?
Gráficos apropriados: Cada visual é o melhor tipo para aquela comparação?
Densidade adequada: Máximo de 7 KPIs/visuais por página?
Performance: Dashboard carrega em menos de 5 segundos?
Mobile-friendly: Funciona em tablet (se aplicável ao público)?

5. Diretrizes Técnicas Power BI

Formatação de Visuais

Títulos: Fonte 14pt, bold, cor Gray-900 (#212121)
Labels de eixo: Fonte 10-12pt, regular, cor Gray-700 (#616161)
Data labels: Mostrar apenas em KPIs e barras (não em linhas com 20+ pontos)
Gridlines: Cor Gray-300 (#e0e0e0), espessura 1px, apenas horizontal
Fundo de visual: Branco (#ffffff) ou Gray-50 (#fafafa)
Bordas: 1px sólida, Gray-300 (#e0e0e0), border-radius 4px

Layout da Página

Fundo de página: Gray-100 (#f5f5f5) - nunca branco puro
Margens: 24px em todos os lados (padding uniforme)
Espaçamento entre visuais: 16px (gap consistente)
Grid: Alinhar todos os visuais em grid de 8px (snap to grid)

Interatividade

Filtros visíveis: Sempre mostre filtros ativos no topo da página. Usuários precisam saber o que estão vendo.

Performance

Máximo de visuais por página: 7 (limite técnico para performance)
Aggregações: Sempre no modelo, nunca no visual (performance crítica)
Tabelas grandes: Limitar a 50 linhas por padrão, usar scroll/paginação

7. Exemplos: Antes vs. Depois

Comparações visuais de problemas comuns e suas soluções seguindo as diretrizes.

Exemplo 1: Gráfico de Pizza com Muitas Categorias

Problema: Pizza com 8+ fatias
Vendas por Categoria
Problemas identificados:
• Impossível comparar fatias similares
• Muitas cores confundem em vez de informar
• Legenda separada dificulta leitura
• Não há hierarquia clara (o que é mais importante?)
Solução: Barra Horizontal Ordenada (Top 5 + Outros)
Melhorias aplicadas:
• Comparação imediata e precisa entre valores
• Ordenação decrescente mostra prioridades
• Top 5 + "Outros" agregado (reduz ruído visual)
• Labels integrados às barras (legibilidade)
• Cor única laranja = uma dimensão de dados

Exemplo 2: KPI Card Sem Contexto

Problema: Valor isolado sem contexto
Receita Total
R$ 2,4M
Problemas identificados:
• Sem referência: é bom ou ruim?
• Não indica ação ou tendência
• Usuário precisa lembrar meta ou comparar manualmente
• Valor absoluto sem significado estratégico
Solução: KPI com contexto, tendência e comparação
Receita Total
R$ 2,4M
+12,5% vs. mês anterior
Meta: R$ 2,2M (109%)
Melhorias aplicadas:
• Comparação vs. período anterior (+12,5%)
• Cor verde indica performance positiva
• Meta explícita com percentual de atingimento
• Seta visual reforça tendência de crescimento
• Usuário entende imediatamente: "está indo bem, manter estratégia"

8. Layout: Grid 8px

Sistema de grid baseado em múltiplos de 8px para criar layouts consistentes e alinhados em todos os dashboards.

Por que 8px? Múltiplos de 8 criam ritmo visual consistente, facilitam alinhamento e funcionam bem em diferentes resoluções de tela.

9. Padrões de Navegação

Diretrizes baseadas em Carbon Design System e Material Design para criar navegação intuitiva e acessível.

Quando Usar Cada Padrão

Tipo de Navegação Quando Usar Exemplo de Uso
Menu Top (Tabs) 3-5 páginas de mesmo nível hierárquico Dashboard: Visão Geral | Vendas | Operações | Financeiro
Menu Lateral 6+ páginas ou hierarquia profunda Sistema: Dashboard / Relatórios / Análises / Configurações
Breadcrumb Navegação hierárquica (3+ níveis) Empresa > Unidade > Departamento > Equipe
Dropdown Seleção de contexto (não navegação) Filtro: Selecione o Período

Posicionamento de Filtros

Filtros no Topo

Use quando: 2-4 filtros principais afetam toda a página

  • Filtros globais (Data, Região, Produto)
  • Aplicam-se a todos os visuais da página
  • Usuário precisa ver filtros ativos sempre

Painel Lateral de Filtros

Use quando: 5+ filtros ou filtros complexos

  • Muitos filtros ocupariam muito espaço horizontal
  • Filtros hierárquicos ou dependentes
  • Painel pode ser colapsável para ganhar espaço

Boas Práticas de Navegação

Sempre mostre filtros ativos: Usuário precisa saber o que está vendo (período, região, etc.)
Máximo de 7 itens no menu: Memória de curto prazo humana suporta 5-9 itens (regra de Miller)
Indique página ativa: Use cor, negrito ou barra lateral para destacar onde o usuário está
Botão "Limpar Filtros": Sempre forneça forma rápida de resetar visualização
Feedback visual: Hover, click e estado ativo devem ter indicação clara
Princípio fundamental: "Onde estou? De onde vim? Para onde posso ir?" - O usuário deve sempre saber estas 3 respostas.
