Design System / Atiaia Energia / Mendix

Mendix Low-Code Platform

Diretrizes para desenvolvimento de aplicações Mendix com identidade visual GCB. Estas orientações respeitam as limitações técnicas da plataforma e seguem as melhores práticas de customização via theme configuration.

Introdução

Filosofia: Configuration over Customization
Mendix utiliza o Atlas UI Design System como base. Nossa abordagem prioriza configuração de tema e uso de widgets nativos ao invés de custom CSS. Isso garante manutenibilidade, responsividade e facilita atualizações da plataforma.

Mendix Atlas UI é o design system nativo da plataforma, baseado em princípios de design consistentes e componentes reutilizáveis. Nossa estratégia é customizar via theme settings, nunca criar soluções paralelas que dificultem manutenção.

Limitações Técnicas: Mendix não suporta web fonts personalizadas (como Praxis Com) fora do contexto de custom styling avançado. A tipografia será limitada às fontes do sistema + Inter (disponível no Atlas UI).

Princípios Fundamentais

Use Atlas UI como Base

Não reinvente componentes. O Atlas UI já é otimizado para responsividade e acessibilidade. Customize apenas o necessário via theme settings.

Atlas UI Documentation

Customização via Theme

Altere cores, espaçamentos e border-radius através das variáveis de tema. Evite CSS custom que pode quebrar em atualizações da plataforma.

Customize Styling Guide

Widgets Nativos First

Priorize widgets nativos do Mendix. Use widgets do Marketplace apenas quando aprovados e mantidos ativamente pela comunidade.

Mendix Marketplace

Mobile-First Responsive

Teste todos os layouts em mobile, tablet e desktop. Use o layout grid system do Atlas UI com breakpoints consistentes.

Layout Widget Reference

Manutenibilidade

Código limpo e documentado. Classes CSS semânticas. Estrutura de pastas organizada para facilitar colaboração entre desenvolvedores.

Zero Gambiarras

Soluções que funcionam hoje mas quebram amanhã são inaceitáveis. Se algo precisa de "hack", busque alternativa dentro das capacidades da plataforma.

Tipografia

Parcialmente Aplicável
Inter: Disponível nativamente no Atlas UI
Praxis Com: Não suportada sem workarounds complexos
IBM Plex Mono: Não suportada (use monospace do sistema)

Solução recomendada: Use Inter como fonte principal. É moderna, tem boa legibilidade e já está integrada ao Atlas UI. Para contextos onde Praxis Com seria ideal (títulos principais), considere usar Inter Semibold/Bold.

// Theme customization - Typography theme: { fontFamily: { primary: 'Inter, -apple-system, sans-serif', heading: 'Inter, -apple-system, sans-serif', mono: 'Menlo, Monaco, monospace' }, fontSize: { h1: '2rem', // 32px h2: '1.5rem', // 24px h3: '1.25rem', // 20px body: '1rem', // 16px small: '0.875rem' // 14px } }

Theme Configuration

Customize o tema Mendix através do arquivo settings.json no diretório theme/ do seu projeto. Abaixo está a configuração recomendada para aplicar as cores GCB:

{ "brandPrimary": "#071d49", "brandSuccess": "#24a148", "brandWarning": "#f1c21b", "brandDanger": "#bb0000", "brandInfo": "#0f62fe", "grayPrimary": "#161616", "grayDark": "#525252", "gray": "#8d8d8d", "grayLight": "#e0e0e0", "grayLighter": "#f5f5f5", "backgroundPrimary": "#ffffff", "backgroundSecondary": "#f4f4f4", "borderRadiusDefault": "4px", "borderRadiusLarge": "8px", "fontFamily": "Inter, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif", "fontSize": "16px", "fontSizeSmall": "14px", "fontSizeLarge": "20px", "fontSizeH1": "32px", "fontSizeH2": "24px", "fontSizeH3": "20px", "spacingSmall": "8px", "spacingMedium": "16px", "spacingLarge": "24px", "spacingExtraLarge": "40px" }
Importante: Após alterar settings.json, execute npm run build para recompilar o tema. Sempre teste em todos os breakpoints (mobile, tablet, desktop).

Login Screen

Tela de Login GCB

Diretrizes Login:

  • Logo GCB centralizada no topo (32px altura, dois círculos laranjas)

O Data Grid é o componente mais usado em Mendix. Use para exibir listas de dados tabulares com paginação, ordenação e ações por linha.

Elemento Diretriz GCB

Rows Background alternado: branco / #fafafa, hover #f5f5f5
Borders Apenas horizontais, #e0e0e0 1px
Paginação Bottom aligned, botões secondary style, mostrar "X de Y resultados"
Actions Ícones ph-pencil-simple (editar), ph-trash (excluir), cor #8d8d8d
Empty State Ícone ph-folder-open, mensagem "Nenhum registro encontrado"

List View

Use List View para exibir dados em formato de cards ou listas verticais. Ideal para dashboards e visualizações mobile.

Mobile-First: List View é melhor para mobile que Data Grid. Configure para empilhar em telas < 768px.
Padrão Implementação
Card Style Border #e0e0e0, border-radius 4px, padding 16px, gap 12px entre cards
Hover Border-color #8d8d8d, elevation-01 (shadow sutil)

Layout Templates

Master Page: Sidebar Navigation

Estrutura:

  • Header: 60px altura, verde #071D49, logo à esquerda, ícones utilitários à direita
  • Sidebar: 240px largura (desktop), background #fafafa, border-right #e0e0e0
  • Content: padding 40px 64px, max-width 1280px
  • Mobile: sidebar colapsa em drawer, header permanece fixo
Dica: Use o wireframe da seção "Navigation" como referência para implementar no Mendix Studio Pro.

Dashboard Layout

Use Template Grid com KPI cards no topo (4 colunas) + gráficos abaixo (2 colunas). Configure breakpoints para empilhar em mobile.

Seção Especificação
KPI Cards Altura 120px, border #e0e0e0, border-radius 8px, padding 24px, gap 24px
Chart Containers Min-height 400px, background branco, border #e0e0e0, padding 24px
Spacing Gap entre seções: 32px (vertical), 24px (horizontal)

Form Layout (2 Colunas)

Quando usar 2 colunas:

  • Formulários com 6+ campos
  • Desktop only (em mobile empilha para 1 coluna)
  • Campos relacionados lado a lado (ex: Nome | Sobrenome)

Especificações:

  • Gap entre colunas: 24px
  • Gap entre campos: 16px (vertical)
  • Labels: acima do input (não à esquerda)
  • Botões de ação: final do formulário, alinhados à direita

Interactive Patterns

Filtros

Padrão Quando Usar
Filtros no Topo Para 1-3 filtros simples (select, date range). Alinhados horizontalmente acima do Data Grid.
Sidebar de Filtros Para 4+ filtros ou filtros complexos (múltiplos checkboxes). Sidebar 280px à esquerda do conteúdo.
Modal de Filtros Mobile only. Botão "Filtrar" abre modal com todos os filtros.
Ver exemplo: Filtros no Topo
Atenção: Sempre mostre quantos filtros estão ativos. Exemplo: "Filtrar (3)" ou badge laranja com número.

Search / Busca

Especificações:

  • Input: 300px largura (desktop), altura 44px
  • Ícone: ph-magnifying-glass à esquerda dentro do input, cor #8d8d8d
  • Placeholder: "Buscar por nome, email..." (específico, não genérico)
  • Posição: topo direito da Data Grid ou List View
  • Comportamento: busca em tempo real (debounce 300ms) ou botão "Buscar"
  • Clear: ícone ph-x à direita quando há texto, clique limpa

Paginação

Use paginação em Data Grids e List Views com mais de 25 itens. Prefira "Load More" para mobile.

Elemento Implementação
Informação "Mostrando 1-25 de 142 resultados" - alinhado à esquerda
Controles Botões Previous/Next + números de página - alinhados à direita
Página Atual Background laranja #071d49, texto branco, não clicável
Outras Páginas Botões secondary style, mostrar no máximo 7 números (1 ... 4 5 6 ... 10)

Breadcrumbs

Estrutura:

  • Posição: abaixo do header, antes do título da página
  • Separador: ph-caret-right ou "/" cinza #8d8d8d
  • Links: cor #0f62fe (interactive blue), hover underline
  • Página atual: texto #525252, não clicável
  • Máximo: 4 níveis (Home > Seção > Subseção > Atual)

States & Feedback

Loading States

Contexto Implementação
Page Load Spinner centralizado, cor primária #071d49, 48px diâmetro
Button Action Spinner dentro do botão (20px), botão disabled, texto "Processando..."
Data Grid Load Skeleton screens: 5 linhas com animação shimmer cinza claro
Inline Load Spinner pequeno (16px) ao lado do texto "Carregando..."

Empty States

Componentes:

  • Ícone: ph-folder-open, ph-magnifying-glass ou ph-list-dashes, tamanho 64px, cor #8d8d8d
  • Título: "Nenhum [item] encontrado", fonte 20px, cor #161616
  • Descrição: texto auxiliar explicando o estado, 14px, cor #525252
  • Ação (opcional): botão primary "Criar [item]" se aplicável
  • Centralizado vertical e horizontalmente

Error States

Tipo de Erro Tratamento
Page Error Ícone ph-warning-octagon 64px vermelho, mensagem "Algo deu errado", botão "Recarregar página"
Form Validation Mensagens inline abaixo de cada campo (ver seção Form Components)
Action Failed Toast notification vermelha #bb0000, duração 4s, ícone ph-x-circle
Network Error Banner no topo da página: "Conexão perdida", cor warning #f1c21b

Success Feedback

Use toast notifications verdes para confirmações de ações (salvar, excluir, enviar). Duração: 2-3 segundos.

Padrão: Toast verde #24a148 canto inferior direito, ícone ph-check-circle, mensagem específica "Item salvo com sucesso".

Responsive Guidelines

Breakpoints

Device Breakpoint Ajustes
Desktop > 1024px Layout completo, sidebar visível, 4 colunas em grids
Tablet 768-1024px Sidebar colapsável, 3 colunas em grids, formulários 2 colunas
Mobile < 768px Sidebar = drawer, 1 coluna, forms empilhados, bottom navigation

Mobile-Specific Patterns

Touch Targets:

  • Tamanho mínimo: 44x44px para todos os elementos clicáveis
  • Espaçamento mínimo entre botões: 8px
  • Botões primary em mobile: full-width com 48px altura

Navigation:

  • Header fixo no topo (60px), com hamburger menu à esquerda
  • Bottom navigation opcional: 56px altura, máximo 5 itens
  • Sidebar drawer desliza da esquerda, overlay escuro com opacity 0.5

Content:

  • Padding lateral: 16px (mínimo)
  • Data Grids: converter para List View em mobile (cards empilhados)
  • Formulários: sempre 1 coluna, labels acima dos inputs
  • Modais: full-screen em mobile (não popups)
Obrigatório: Teste TODAS as telas em mobile antes de homologar. Use Chrome DevTools ou dispositivo real.

Não Fazer (Anti-patterns)

Critical: Estas práticas são proibidas
Violações podem resultar em aplicações quebradas, difíceis de manter ou inacessíveis.
Não Faça Isso Faça Isso Ao Invés
Custom CSS com !important para sobrescrever Atlas UI Configure via settings.json ou use classes do Atlas UI
Usar cores fora da paleta GCB Mapear todas as necessidades para as 6 cores brand + 4 semânticas
Widgets de marketplace não aprovados Use apenas widgets nativos ou aprovados pela equipe Tecnova
Hardcode de valores (px, cores) direto nos widgets Use variáveis de tema e classes reutilizáveis
Layouts que quebram em mobile/tablet Teste em todos os breakpoints antes de homologar
Textos em imagens (não acessível, não traduzível) Use texto HTML estilizado + ícones quando aplicável
Ignorar estados de foco (acessibilidade) Garanta que todos os elementos interativos têm focus state visível
Micromanage layout com absolute positioning Use layout grid e flexbox do Atlas UI
