Design System / VIVIX / SAP BTP

SAP Business Technology Platform

Diretrizes para aplicações SAP BTP (UI5, Fiori) seguindo a identidade visual GCB. Este guia cobre customização de temas, componentes UI5 e padrões SAP Fiori adaptados para o Grupo Cornélio Brennand.

Introdução

SAP BTP (Business Technology Platform) é a plataforma de desenvolvimento da SAP para criar aplicações corporativas. As aplicações seguem o SAP Fiori Design System e utilizam SAPUI5 como framework.

Filosofia: Theme Before Custom
Customize a aplicação através de temas SAP (Theme Designer) ao invés de CSS custom. Isso garante compatibilidade com atualizações e consistência visual.

Stack tecnológico:

  • Framework: SAPUI5 (OpenUI5 para projetos open source)
  • Design System: SAP Fiori 3
  • Theming: SAP Theme Designer ou UI Theme Designer
  • Ícones: SAP Icons (built-in) + Phosphor Icons (suplementar)
  • Tipografia: SAP 72 (padrão Fiori) ou Inter (alternativa GCB)

Princípios Fundamentais

Fiori First

Use componentes e padrões Fiori nativos. Eles já são otimizados para responsividade, acessibilidade e UX corporativa.

SAP Fiori Design Guidelines

Theme Designer Only

Customize cores e espaçamentos via Theme Designer. Evite CSS custom inline que pode quebrar com atualizações da SAP.

UI Theme Designer Docs

Floorplans Padrão

Use Fiori Floorplans (List Report, Object Page, Overview Page). Não crie layouts do zero.

Fiori Floorplans

Responsive by Default

Componentes UI5 são responsivos nativamente. Configure breakpoints mas não recrie comportamentos mobile.

Acessibilidade WCAG

Fiori já cumpre WCAG 2.1 AA. Mantenha labels, ARIA roles e keyboard navigation funcionando.

Performance First

Lazy loading de views, paginação server-side em tabelas, cache de dados. Siga SAP Best Practices.

Fiori Elements (Templates)

Fiori Elements são templates prontos para acelerar desenvolvimento. Use ao invés de criar telas do zero.

Template Quando Usar
List Report Listagem de dados com filtros, busca e ações. Exemplo: Lista de pedidos, usuários, produtos.
Object Page Detalhes de um registro com header, facets e seções. Exemplo: Detalhe de pedido, perfil de usuário.
Overview Page Dashboard com cards KPI e gráficos. Exemplo: Visão geral de vendas, operações.
Worklist Lista simples de tarefas/items. Exemplo: Aprovações pendentes, notificações.
Analytical List Page Listagem com visualização analítica (gráficos + tabela). Exemplo: Análise de vendas por região.
Priorize Fiori Elements sobre Freestyle UI5
Fiori Elements gera automaticamente UI baseada em metadados OData. Menos código, mais manutenibilidade.

Tables

Diretrizes:

  • Use sap.m.Table para listas mobile-friendly
  • Use sap.ui.table.Table para dados tabulares complexos (desktop)
  • Header: background #f5f5f5, texto #161616 bold
  • Rows alternadas: branco / #fafafa
  • Hover: #f5f5f5
  • Paginação: sempre server-side para mais de 100 registros

Forms (sap.ui.layout.form)

Estrutura recomendada:

  • Use SimpleForm para formulários simples
  • Labels sempre acima dos inputs (não à esquerda)
  • Inputs altura mínima: 44px (touch-friendly)
  • Required fields: asterisco vermelho #bb0000 após label
  • Validação: ValueState="Error/Success/Warning" com mensagem inline

Padrões de Layout

Shell (sap.m.Shell + ShellBar)

Especificações:

  • ShellBar altura: 44px (mobile) / 56px (desktop)
  • Background: #005751 (verde escuro GCB)
  • Logo GCB à esquerda (60px largura)
  • Título da aplicação: branco, fonte SAP 72 Bold 16px
  • Ícones utilitários à direita (notificações, perfil)

Layout Responsivo (sap.ui.layout)

Breakpoint Tamanho Comportamento
Phone < 600px 1 coluna, navegação bottom bar, tabelas viram cards
Tablet 600-1024px 2 colunas, side navigation opcional
Desktop > 1024px 3-4 colunas, master-detail layouts

Master-Detail Pattern

Quando usar:

  • Lista de items à esquerda (Master) + detalhe à direita (Detail)
  • Master: 320-400px largura fixa
  • Detail: flex grow, min-width 600px
  • Mobile: empilha (Master como drawer)

Input States

Warning Warning Border #f1c21b, mensagem amarela

Validation Messages

Diretrizes:

  • Validação em tempo real (onBlur ou onChange)
  • Mensagens específicas: "Email inválido" ao invés de "Erro"
  • Use MessageBox para erros críticos de submit
  • Use MessageToast para confirmações (ex: "Salvo com sucesso")
  • Required fields: asterisco após label + validação obrigatória

Data Display

Object Page (Fiori Pattern)

Estrutura:

  • Header: Título + status + ações principais
  • Header Facets: KPIs e informações resumidas
  • Sections: Conteúdo detalhado organizado em abas/seções
  • Footer: Ações de salvar/cancelar (fixo no bottom)

Charts (sap.viz / sap.suite.ui.microchart)

Paleta de cores GCB para gráficos:

  • Categórica: #00b2a9, #005751, #0f62fe, #24a148, #f1c21b, #bb0000
  • Sequencial (baixo → alto): #ffe4cc → #00b2a9 → #005751
  • Divergente (negativo ↔ positivo): #bb0000 ↔ #f5f5f5 ↔ #24a148

Responsive Design

Device-Specific Guidelines

Device Ajustes
Mobile - Tables viram List com cards
- Forms sempre 1 coluna
- Navegação: bottom bar ou drawer
- Touch targets mínimo 44x44px
- Padding reduzido: 16px ao invés de 32px
Tablet - Forms podem ter 2 colunas
- Master-Detail funciona lado a lado
- Navegação: side panel colapsável
- Padding: 24px
Desktop - Layout completo (3-4 colunas)
- Tables com todas as colunas visíveis
- Navegação: sidebar fixa
- Padding: 32-48px
Obrigatório: Teste em dispositivos reais (não apenas emuladores). Use SAP Fiori Client app para testes mobile.

Não Fazer (Anti-patterns)

Evite estas práticas que quebram padrões Fiori:
Não Faça Isso Faça Isso Ao Invés
CSS custom com !important Use Theme Designer para customizar cores e espaçamentos
Criar layouts do zero sem Fiori Floorplans Use List Report, Object Page ou Overview Page templates
Usar cores fora da paleta GCB Siga as 6 cores principais + grayscale definidas
Tabelas sem paginação server-side Sempre pagine no backend para mais de 100 registros
Ignorar responsividade mobile Teste em Phone/Tablet/Desktop e ajuste layouts
Remover estados de foco (keyboard navigation) Mantenha acessibilidade WCAG 2.1 AA
Hardcode de textos (sem i18n) Use arquivos i18n para internacionalização
Misturar versões de UI5 (1.84 + 1.108) Use uma única versão de UI5 por aplicação
